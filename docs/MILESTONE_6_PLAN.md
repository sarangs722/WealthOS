# Milestone 6 — Hardening and release readiness

Authorized by the user's “go ahead” after Milestone 5. Work stays in the existing native Android app; device writes/tests are isolated to named WealthOS emulators.

1. Implement a documented, versioned portable backup using PBKDF2-HMAC-SHA256 (600,000 iterations, random 256-bit salt) and AES-256-GCM (random 96-bit nonce, authenticated header, 128-bit tag). No Keystore/database key is exported. Use standard platform crypto; no new cryptographic dependency. Bound inputs and reject tampering, wrong passwords, unknown versions and truncation before parsing or mutation.
2. Export all normalized financial tables in one consistent database transaction using typed, lossless binary rows. No raw WAL/database copying or plaintext temporary files. Validate imported rows against a packaged trusted schema in a fresh encrypted staging database, run the explicit migration chain, check SQL integrity/foreign keys and domain validity. Never execute DDL from a backup.
3. Restore as an explicit replacement transaction with a current-vault fingerprint check, an authenticated encrypted pre-restore safety backup, atomic rollback and retained imported audit history. Keep local device credentials/keys on the receiving device; disable public networking after restore. Preserve old safety backups; no silent pruning or merge/double-counting.
4. Add native SAF export/import, password confirmation and preview/replacement controls, encrypted safety-backup export, failure/offline states and memory-only password fields. No extra storage permission. Verify reinstall/new-key portability on synthetic data.
5. Exercise backups, corruption/partial IO, failed restores, concurrent edits, all existing migrations, API 29 and API 36 where build environment permits. Run finance, repository and UI regression, lint, actual debug build/launch and populated 0.5→0.6 upgrade.
6. Build/shrink release artifacts, verify native 16 KiB packaging/alignment, inspect dependencies/permissions and lifecycle handling, review large-font layouts, and document reproducible build/signing and security limitations. Production signing requires a user-controlled key; no secret credentials will be invented or checked into the repository. Independent external security review and physical biometric/hardware assurance cannot be claimed from emulator tests.

Portable format v1 starts with schema 6, captures all financial/audit/public-cache rows, supports future schema migration through trusted packaged schemas, and limits the encoded financial payload to 8 MiB / 50,000 rows. Exceeding bounds fails without changing financial records. Passwords are not recoverable; plaintext necessarily exists in process memory during use, with best-effort key/password clearing.
