# Public sources — verification and usage decisions

Verified 27 October 2026 against official publications, API documentation/source, and real public responses. No paid provider, API secret, brokerage integration or private financial upload is used. No third-party network/parser dependency was added.

MoSPI: the MIT license on its reference **code** is not asserted to license all published data. WealthOS stores only minimal published numerical statistics for personal reference, attributes MoSPI and links official guidance; it redistributes no portal content, logos or full dataset. Its reference Python client is **not** adopted: the app uses normal platform HTTPS validation, never disables TLS verification, and has no reference-client telemetry. If authentication or format requirements change, refresh fails closed and retains cached data. No general right to redistribute third-party content is claimed.

Automatic stock/ETF/commodity prices remain unavailable: no free authorized adapter was established in this milestone. Manual prices remain fully functional. Official bank rate publications can be cited in manual economic references; they cannot replace contracted FD/RD/loan rates.

Live Android verification found BIS v2 includes `OBS_STATUS=M`, `OBS_VALUE=NaN` on missing calendar days, including weekends/holidays. [BIS SDMX technical definitions](https://www.bis.org/statistics/bankstatsguide_tech.pdf) identify M as missing and F as free for publication. The parser validates date/source/units/confidentiality, skips only explicitly missing M rows with empty/NaN values, and retains gaps without interpolation or zero substitution. Numerical values marked M, missing values marked A, unknown statuses and duplicate dates fail closed. An entirely missing batch remains unavailable.

The AMFI-format NAV observation is interpreted as the closing NAV for its stated financial date, consistent with AMFI's daily NAV guidance (accessible from its homepage). Same-date splits/bonuses are already included in that closing price even if entered later; later-date actions still adjust carried prices as estimates. This timing convention affects valuation only: it never invents allotments or determines a purchase/redemption's actual applicable NAV, settlement or cut-off eligibility. Those transactions remain explicitly entered by the user.

## Transport, validation and persistence

Network access defaults off, including after migration. Refresh happens only from an explicit button. No startup request, worker, scheduler or background sync exists. Requests are fixed, provider-specific, generic statistical URLs: no account, instrument, amount, goal or scenario fields. The app supplies no credentials/cookies and accepts no arbitrary request URL. Opening an attributed source uses an explicitly labeled external-browser button.

Platform HTTPS, 15-second connect/read timeouts, no redirects, no HTTP/cleartext, identity encoding, strict UTF-8, expected content types and bounded responses (ECB/CPI 128 KiB, BIS 512 KiB) apply. XML entities/DTDs, duplicate/conflicting rates, unexpected namespaces, wrong units/bases/sectors, non-string CPI decimals, incomplete pagination, wrong fund identity and missing/nonpositive prices fail validation. No guessed value replaces an unavailable response. Files are bounded to 16 MiB decoded characters, 120,000 lines and 4096 characters per line; only one selected fund is persisted, not the source file/URI.

Each cached observation retains provider, series, source URL, observation date, retrieval instant, native currency/units, validation provenance, publication/basis notes, exact value, source identity, SHA-256 deduplication fingerprint and append-only revision. Current freshness is computed from the source date: NAV/FX 4 days, CPI 45, policy 14, bank reference 30. These are documented usability thresholds, not claims of market availability. Applied FX also retains the ledger's existing seven-day valuation warning.

Refresh success/failure is recorded; failure never discards cache or modifies finances. Partial batches never commit. Same-date corrected observations append revisions; identical values/metadata deduplicate. BIS rolling query-window changes alone do not create false revisions. Historical observations are retained. Network fetching is separate from SQL transactions; validation, cache rows, refresh result and audit commit atomically.

NAV/FX application is explicit, requires review and retains earlier financial revisions. Import does not apply a quote. Application is atomic with provenance/audit and idempotent per source observation and target. Current exact scheme/optional ISIN binding is rechecked. Cached application works offline. An older quote cannot supersede a newer financial date. Unit-price quotes may predate a Quick Add opening; no holdings/transactions before opening are invented. Economic references never alter scenario assumptions, salary, contract rates, or bank balances. Screens respect obscured amounts; demo data is explicitly fictional, read-only and memory-only.
