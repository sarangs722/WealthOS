# 16 KiB userspace runtime verification

October 28, 2026. **Software runtime checks completed with the limitations below.** This continues Milestone 6 release verification. No personal phone, existing WealthOS/WealthOS29 emulator, production key or financial source code was changed.

## Environment and scope

Two new, isolated AVDs are used: `WealthOS16K` / `emulator-5558` / Android 15 API 35 / 1080×1920, and `WealthOS16K36` / `emulator-5560` / Android 16 API 36 / 1080×2400. Both use x86_64, 4 GiB RAM and Asia/Kolkata timezone; `getconf PAGE_SIZE` reports **16384**. Only one runs at a time. Google describes these x86_64 targets as simulations of 16 KiB userspace alignment on a 4 KiB kernel; they are not physical ARM hardware or hardware-backed Keystore assessments. See [Google's technical explanation](https://android-developers.googleblog.com/2024/08/adding-16-kb-page-size-to-android.html) and [Android's testing guidance](https://developer.android.com/guide/practices/page-sizes#16kb-emulator).

The official stable image is `system-images;android-35;google_apis_ps16k;x86_64`, revision 5. The user explicitly accepted its supplied SDK terms before download. The 1,696,342,085-byte archive matched Google's published SHA-1 `d709cf26b375abecfbbf5803afd20749ddfa2865`; independently recorded SHA-256 is `61ae26a86ec209e200337fcd04329c2f568b1d920d4e555712dec95fd89c22ec`. The image was extracted to a new workspace directory; existing SDK images and AVD data were preserved.

The newer official image is `system-images;android-36.1;google_apis_ps16k;x86_64`, revision 4, using the identical accepted license text in the same Google catalog. Its 1,913,923,004-byte archive matched published SHA-1 `d812164d3704c2d5846d34e0a4d2c61cb1224a02`; SHA-256 is `a2e3817918c991ba6607bbd1e63503bf546e2bc0ddaed0c72ef9c855a4173e9f`. The installed emulator 36.3.10 meets both images' published minimum versions. Both were extracted only after disk-headroom and checksum checks.

## Verification approach

1. Build the real app and database/network/app test APKs. This completed successfully in 8 seconds (173 up-to-date tasks). The development app remains the verified 0.6.0 APK, SHA-256 `71baccb417015beac48139fc2e4855c423ab46655d0e86ce720ece30c2fe5cd0`.
2. Run all 58 database, seven network and 18 app instrumentation cases through the exact emulator serial. The runner checks AVD name, API, ABI, boot completion and actual userspace page size, then checks executed-case counts, final JUnit success and absence of failures/skips. It cannot target a personal phone and never clears a vault.
3. Exercise the unchanged minified coexisting release with a disposable signer and a known fictional portable backup. Native encrypted database loading, actual file selection, confirmed restoration and cold-start values are checked separately from the debug instrumentation suites.

The runner is [Verify-16KiBRuntime.ps1](../scripts/Verify-16KiBRuntime.ps1). After building all test APKs and starting the fresh named AVD:

```powershell
.\scripts\Verify-16KiBRuntime.ps1 `
  -SdkDirectory $env:ANDROID_HOME `
  -Serial 'emulator-5560' `
  -IsolateAppTests `
  -OutputDirectory '.tools\release-16k\new-runtime-run'
```

The initial 2 GiB AVD attempt executed **zero** cases: Android's process-exit record identified `LOW_MEMORY`. It was not counted as passing. The owned emulator was stopped, its RAM increased to 4 GiB and the idle build daemon released. No app or test data was cleared. The `-ResumeBeforeAppTests` option permits this specific recovery only while the app has never been launched, the package inventory is expected and installed APKs match their host SHA-256 hashes; it does not update or uninstall them. A fresh output directory retains the failed run's diagnostics.
